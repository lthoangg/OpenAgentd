## Rules for every topic

- Change configuration files, or use the `mcp` and `workspace` tools where a
  reference says so — no OpenAgentd code changes.
- Never restart OpenAgentd from `shell`; it ends the current turn. When a
  change needs a restart, tell the user.
- Use absolute paths; file tools refuse `~`.
- Secrets: `.env` is off-limits to the file tools. API keys and logins go
  through Settings → Providers or `agentd auth <provider>`. Never write a
  secret into a config file without the user's explicit consent.
- This skill's own files are read-only and regenerated by OpenAgentd. To
  customise a bundled skill, write one with the same `name` under
  `{SKILLS_DIR}` — it takes precedence.

## Workflow

1. **Read the reference** for the topic, then **read the target file**.
2. **Compute the minimal diff** — change only what was asked; never reformat unrelated lines.
3. **Show a `diff` block** with a one-line summary.
4. **Wait for confirmation** unless the request was already explicit — then apply in the same turn after showing the diff.
5. **Apply with `patch`** (it creates parent directories). Patch reports any
   failure, so there is no need to read the file back.
6. **Report** what changed, which file, and when it takes effect.

MCP servers and workspace groups change through their tool instead: the call
shows the user a card and applies only on **Apply**, so skip steps 3–5 and
don't ask first.

## Failure modes

- **File not found** → confirm the name; list the directory to show what exists.
- **Malformed frontmatter or JSON/YAML** → show the problem; don't repair unless asked.
- **Request outside these topics** (code changes, OS setup) → say so and suggest the right path.
